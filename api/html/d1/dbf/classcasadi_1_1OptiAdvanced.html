casadi::OptiAdvanced Class Reference

Opti with debugging and low-level access. More...

#include <optistack.hpp>

Detailed Description

Obtained through Opti::debug or Opti::advanced; it is a deep copy of the Opti instance with the methods below added. No API stability is guaranteed for these methods. Most of them bake the problem (flatten variables and constraints) on the fly, so they also work on a copy that has not been solved.

Extra doc: https://github.com/casadi/casadi/wiki/L_2mz

static MX casadi::Opti::bounded ( const MX &  lb,
const MX &  expr,
const MX &  ub 
)
inlinestaticinherited

Returns the expression (lb <= expr) <= ub, which subject_to() recognizes as a double-bounded constraint lb <= expr <= ub when lb and ub are free of decision variables. Identical to writing lb <= (expr <= ub) by hand; provided because Python's chained comparison lb <= expr <= ub raises an error for MX. A static method; the instance is not needed.

>>> opti = Opti()
>>> x = opti.variable(2)
>>> opti.subject_to(opti.bounded(-1, x, 1))
>>> opti.subject_to(Opti.bounded(0, x[0] + x[1], 1))
>>> opti.ng, opti.lbg, opti.ubg
(3, MX(vertcat(all_-1(2x1), 0)), MX(ones(3x1)))

◆ casadi_solver()

Returns an OptiAdvanced deep copy of the current state: same symbols, constraints, values and latest solver result, with extra methods such as value() at a non-converged iterate, show_infeasibilities(), x_describe()/g_describe() and casadi_solver(). Changes to the copy do not affect the original. No API stability is guaranteed for the extra methods. In Python this is a read-only property: opti.debug.value(x).

...   opti.solve()

0.36

void casadi::Opti::subject_to ( const MX &  g,
const Dict &  options = Dict()

inherited

g is a comparison expression built with ==, <=, >= (< and > behave as <= and >=). Vector expressions give one constraint per element; both sides may be vectors of the same shape or a scalar that is broadcast. Each call appends to the constraint set.

Recognized forms and how they reach the solver:

  • g(x,p) <= b(p), b(p) <= g(x,p), g(x,p) == b(p): one side free of decision variables becomes the bound (lbg/ubg) and the other side the constraint expression g.
  • lb(p) <= (g(x,p) <= ub(p)): a chained inequality whose outer sides are free of decision variables becomes a double-bounded constraint lb <= g <= ub (one row). Both bounds may be vectors. In Python the inner comparison must be parenthesized, because the plain chain 0 <= x <= 1 asks for the truth value of an MX and raises an error; bounded() builds the same expression.
  • g1(x,p) <= g2(x,p), g1(x,p) == g2(x,p): both sides depend on variables, giving g1-g2 <= 0 or g1-g2 == 0. A double-bounded constraint on a pure decision variable, such as -1 <= (x <= 1), is still passed as a constraint row; set the nlpsol option "detect_simple_bounds" in solver() to have it moved to the variable bounds lbx/ubx.

Errors: a constant comparison, an empty or fully sparse expression, a symbol not declared by this instance, and dual variables all raise an error immediately. A square matrix comparison A >= B is interpreted as a semidefinite constraint, which "nlp" does not support: vectorize the matrix with vec(A) for an elementwise constraint. An expression without comparison operator is accepted but rejected at solve().

Returns an MX symbol of the requested shape, registered with this Opti instance. Variables are stacked into the solver's x vector in order of creation, so the order of variable() calls determines the layout of x and of lam_x. A variable that does not appear in the objective or the constraints is simply left out of the problem, but asking for its value after solve() raises an error.

With attribute "symmetric" (square shapes only) the returned expression is a symmetric matrix built from n*(n+1)/2 underlying scalars.

The default initial guess is 0; change it with set_initial().
