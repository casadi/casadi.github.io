Detailed Description

Create an NLP solver

Returns a Function that solves the parametric nonlinear program (NLP) 

min          F(x, p)
x

subject to
LBX <=   x    <= UBX
LBG <= G(x, p) <= UBG
p  == P

nx: number of decision variables
ng: number of constraints
np: number of parameters

The problem is given as a dictionary with fields "x" (decision variables, a dense vector), "f" (scalar objective), and optionally "p" (parameters, dense vector) and "g" (constraint expression, dense vector). All entries must be of one symbolic type (SX or MX). A missing "f" is taken as 0 and a missing "g" as an empty vector; any other field name is an error, as is a symbol in "f" or "g" that is not part of "x" or "p". The problem can also be given as a Function with inputs "x", "p" and outputs "f", "g" (for instance one created with external), as the name of a shared library or a ".c" file (compiled on the fly with clang) containing such a function named "nlp", as an Importer, or as an NlpBuilder (an .nl file).

The returned Function has inputs x0, p, lbx, ubx, lbg, ubg, lam_x0, lam_g0 (see nlpsol_in) and outputs x, f, g, lam_x, lam_g, lam_p (see nlpsol_out). Call it with keyword arguments (returns a dictionary) or positionally with all 8 inputs (returns a tuple). Omitted inputs take their defaults: -inf for lbx and lbg, +inf for ubx and ubg, 0 otherwise (see nlpsol_default_in). A scalar passed for a vector input is broadcast to every entry. An input with lb > ub, lb = +inf or ub = -inf raises an "Ill-posed problem" error.

Multiplier convention: lam_x and lam_g are the Lagrange multipliers of the bound constraints on x and g; a multiplier is negative when the lower bound is active and positive when the upper bound is active, such that grad_x f + jac_x(g)' lam_g + lam_x = 0 at the solution. lam_p is the multiplier of p == P, i.e. minus the gradient of the optimal objective with respect to p. lam_x0 and lam_g0 are only used by solvers that support warm starts.

When the solver does not converge, the result still holds the last iterate and stats() reports "success" False and the plugin-specific "return_status"; with option "error_on_fail" True an exception is raised instead (default False for nlpsol).

Options common to all plugins (the plugin options follow in the tables below):

  • "expand": convert an MX problem to SX before creating the derivative functions (default false). Usually faster evaluation; fails on nodes without SX support.
  • "print_time": print a timing table after each call (default true for nlpsol).
  • "error_on_fail": raise on an unsuccessful solve (default false).
  • "calc_lam_x", "calc_lam_p", "calc_f", "calc_g": recompute lam_x (from the stationarity condition), lam_p, f and g in the base class from the solution returned by the plugin (defaults false, true, false, false). "calc_multipliers" sets calc_lam_x and calc_lam_p.
  • "bound_consistency": after the solve, clip x and g to their bounds and set each multiplier to the sign of its active bound, or 0 when both bounds are infinite (default false).
  • "discrete": list of nx booleans marking integer variables; requires a plugin with integer support, otherwise an error at construction.
  • "equality": list of ng booleans hinting which constraints have equal bounds.
  • "warn_initial_bounds": warn when x0 violates lbx or ubx (default false).
  • "iteration_callback": a Function (typically a Callback) with the nlpsol output scheme as inputs, called every "iteration_callback_step" iterations with the current iterate.
  • "detect_simple_bounds": move entries of g that are bounds on a single variable into the simple bounds lbx/ubx (default false).
  • "verbose", "monitor", "show_eval_warnings", "common_options", "specific_options": control diagnostics and the options of the generated derivative functions.

Plugin options are passed in a nested dictionary under the plugin name (e.g. {"ipopt": {"print_level": 0}}) or dotted ("ipopt.print_level"). The call to the returned Function can be embedded in an MX expression and differentiated: the sensitivities of the primal-dual solution with respect to any input follow from the KKT conditions.

>>> x = SX.sym("x"); y = SX.sym("y"); p = SX.sym("p")
>>> nlp = {"x": vertcat(x, y), "p": p, "f": (1 - x)**2 + p*(y - x**2)**2, "g": x + y}
>>> opts = {"ipopt.print_level": 0, "ipopt.sb": "yes", "print_time": False}
>>> S = nlpsol("S", "ipopt", nlp, opts)
>>> print(S)
S:(x0[2],p,lbx[2],ubx[2],lbg,ubg,lam_x0[2],lam_g0)->(x[2],f,g,lam_x[2],lam_g,lam_p) ...
>>> sol = S(x0=[2.5, 3.0], p=100, lbg=-1, ubg=1)
>>> sol["f"], sol["x"]
(DM(0.1456), DM([0.6188, 0.3812]))
>>> S.stats()["success"], S.stats()["return_status"]
(True, 'Solve_Succeeded')
>>> x_opt, f_opt, g_opt, lam_x, lam_g, lam_p = S([2.5, 3.0], 100, -inf, inf, -1, 1, 0, 0)
>>> f_opt, lam_g
(DM(0.1456), DM(0.3407))
>>> S(p=100)["x"]
DM([1, 1])

Fatrop is a solver developed at KU Leuven by Lander Vanroye and Wilm Decre. The algorithm is based on IPOPT, but the linear algebra is much more efficient.

With structure_detection = 'none' (default), it will behave as a general-purpose dense nonlinear program solver.

With structure_detection = 'manual', you can specify a block structure.

Let's say you perform multiply shooting with a system

x_k+1 = A_k x_k + B_k u_k

Suppose your constraint Jacobian looks like: 

 nx0  nu0  nx1  nu1  nx2  nu2
 -----------------------------

nx1 |A0 B0 I0
ng1 |C0 D0
nx2 | A1 B1 I1
ng2 | C1 D1
ng3 | C2 D2

with n* capturing the number of states, inputs, and constraints in each block.

You can then specify this structure with:

N = 2 nx = [nx0 ,nx1, nx2] nu = [nu0, nu1, nu2] ng = [ng1, ng2, ng3]

With structure_detection = 'auto', the block-defining parameters nx, nu, ng, and N are automatically detected from the sparsity pattern.
