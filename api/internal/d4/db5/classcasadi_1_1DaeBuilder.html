casadi::DaeBuilder Class Reference

A symbolic representation of a differential-algebraic equations model. More...

#include <dae_builder.hpp>

Detailed Description

A DaeBuilder holds a list of uniquely named model variables with FMI-style meta data (causality, variability, type, start value, bounds, unit, ...) together with the model equations. The model is either built symbolically with add, eq, when and friends, or imported from an FMU / modelDescription.xml (constructor with a path, load_fmi_description). Numerical evaluation goes through the function factory create, which returns differentiable Function objects.

Every variable belongs to at most one CasADi category, derived from its causality, variability and defining equation:

Variables: 

t:      independent variable (usually time)
c:      constants
p:      parameters
d:      dependent parameters (time independent)
u:      controls
w:      dependent variables  (time dependent)
x:      differential states
z:      algebraic variables
q:      quadrature states
y:      outputs

Equations: 

differential equations: \dot{x} ==  ode(...)
algebraic equations:          0 ==  alg(...)
quadrature equations:   \dot{q} == quad(...)
dependent parameters:         d == ddef(d_prev,p)
dependent variables:          w == wdef(w_prev,x,z,u,p,t)
output equations:             y == ydef(...)
initial equations:     init_lhs == init_rhs(...)
events:      when when_cond < 0: when_lhs := when_rhs

The category names ("x", "ode", ...) are the strings accepted by all, inputs, outputs, create and the other category-based members. Internal helper variables (named der(x), __alg__0, __assign__.., __when__0, ...) are created as equations are added; they show up in all().

>>> dae = DaeBuilder("rocket")
>>> a = dae.add("a", "parameter", "tunable")
>>> u = dae.add("u", "input")
>>> h = dae.add("h", dict(start=0))
>>> v = dae.add("v", dict(start=0, unit="m/s"))
>>> m = dae.add("m", dict(start=1))
>>> dae.eq(dae.der(h), v)
>>> dae.eq(dae.der(v), (u - a*v**2)/m - 9.81)
>>> dae.eq(dae.der(m), -u**2)
>>> dae.x(), dae.u(), dae.p()
(['h', 'v', 'm'], ['u'], ['a'])
>>> f = dae.create("f", ["x", "u", "p"], ["ode"])
>>> f
Function(f:(x[3],u,p)->(ode[3]) MXFunction)
>>> f([0, 0, 1], 1, 0.5)
DM([0, -8.81, -1])

Without path, the instance starts empty and the model is built symbolically with add and eq. With path, the model description is imported immediately:

  • a directory containing modelDescription.xml (an unzipped FMU),
  • a .fmu archive (requires a build with WITH_GHC_FILESYSTEM=ON; it is unzipped to a temporary directory that is removed once nothing references it any more),
  • a .bmo Base Modelica file (requires the lacemodelica ModelicaParser plugin).

An imported standard FMU is not symbolic (symbolic() is false): equations are evaluated by calling the FMU binary, so create is available but oracle, eq, eliminate etc. are not.

Parameters
nameInstance name; used as default function name prefix by create(), transition() and export_fmu
pathModel to import, see above; empty for a symbolic model
optsOptions (any other key is an error):
  • "debug" (bool, false): print debug information during import and enable FMU logging
  • "fmutol" (double, 0): tolerance passed to the FMU
  • "ignore_time" (bool, false): do not expose the hidden time variable of an imported model that declares no independent variable
  • "detect_quad" (bool, false): classify differential states that do not appear in any right-hand side as quadrature states q
  • "resource_serialize_mode" (string): how an imported FMU is serialized with functions created from it, "link" or "embed"
  • "enable_ls_dae" (bool, true): honour the DAE layered standard of an FMU
  • "enable_ls_serialization" (bool, true): honour the serialization layered standard of an FMU

  • "parameter": "tunable" gives p (c for non-floating-point types), "fixed" gives c; other variabilities are an error
  • "calculatedParameter": d; requires "fixed" or "tunable"

◆ eq()

void casadi::DaeBuilder::eq ( const MX &  lhs,
const MX &  rhs,
const Dict &  opts = Dict() 
)

Adds the equation lhs == rhs and reclassifies variables accordingly:

  • lhs is the derivative of a state (der(x)): the equation becomes the ODE of x, which moves from z to x; der(x) becomes a dependent variable w
  • lhs is a variable of category z: the equation is its binding equation and the variable moves to w; it must not have a binding equation already
  • lhs is a concatenation of such variables: split into one equation per component
  • lhs is anything else, typically 0: an implicit (algebraic) equation 0 == lhs - rhs is added to outputs("alg"); a second equation for a variable that already has a binding equation is treated this way too

A derivative der(x) that appears in rhs before it was defined is replaced by a new algebraic variable der_x with the trivial ODE der(x) == der_x, keeping the DAE semi-explicit. Scalar sides are broadcast to the length of the other side; sparse sides are densified. Variables appearing in rhs are marked as used, so a quadrature state q referenced there becomes a regular state x.

rhsColumn vector expression in model variables only; dimensions must match after broadcasting
